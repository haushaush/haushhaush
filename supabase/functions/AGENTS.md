# Edge function rules

- Bonus checkup sync: `bonus-checkins-sync` is the only writer of Close-sourced `bonus_checkins`; it resolves the key containing Client Checkin, verifies lead mappings, writes nothing on Close errors, and logs every run. Why: failed fetches must never silently replace the observed call data.
- Bonus cash collect: `bonus-cash-sync` is the only writer of Qonto-sourced `bonus_cash_collect`; it counts paid invoices at full net (no ad-budget deduction), deduped by a source-independent invoice key; the cockpit clarification list suggests customers via `namensTreffer` and links only after confirmation. `bonus-berechnung` compares a running month against the same day span of the reference month. Why: invoices are more complete than bank lines, and partial months must be compared fairly.
- Bonus survey intake uses server-side matching, service-only atomic rate-limit/save RPCs and an authenticated admin assignment RPC; customer/month uniqueness is enforced in PostgreSQL and the UI shares the server name-similarity helper. Why: concurrent submissions must not double-count or bypass manual review, and suggestions must agree with automatic matching.
- bonus-cash-sync: match Qonto invoices by qonto_client_id first; name fallback only if all links with that normalized name point to one client, else Klärliste. Why: same-named Qonto records may be different customers.
